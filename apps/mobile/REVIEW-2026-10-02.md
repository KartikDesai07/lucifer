# Mobile / printer review — 2 October 2026

## Architecture and Kotlin comparison

The React Native app stays the mobile client. Its screens collect the POS
address and handle loading/errors; the cafe React website owns the POS and
printer settings UI. Kotlin under this app remains the Android transport layer
for Bluetooth Classic, BLE, USB printer class and private-network TCP.

Reviewed `D:/kd/Sandbee-mobile`: Compose onboarding has a consistent navy/blue
palette, clear field hints, loading feedback and a hardened WebView. Its source
contains no receipt-printer transport implementation. The React app now adopts
the clearer onboarding/card treatment and feedback, while retaining this
project's URL rules, authenticated printer bridge and print-host flow.

Windows cable printing belongs to `apps/desktop`: it sends ESC/POS through the
Windows spooler or uses the configured driver method. A phone does not directly
own a printer plugged into another PC; designate that PC as the printing device
to route mobile orders there.

## Findings and changes

1. **Missing colors:** `adb shell dumpsys webviewupdate` reported Android WebView
   `109.0.5414.123`. The running POS had layout and a blue primary control but
   black borders and missing semantic colors. The cafe stylesheet uses Tailwind
   v4 and OKLCH tokens, unsupported in that engine. PostCSS now emits RGB
   fallbacks after Tailwind, and places modern custom-property overrides inside
   feature queries. The regression test compiles production CSS and checks the
   token fallbacks. Tailwind's existing opacity fallback may be more saturated
   on an old engine; updating WebView is still preferable for full fidelity.
   Official browser baseline: <https://tailwindcss.com/docs/compatibility>.
2. **USB hidden without Bluetooth:** the native printer list was inside a
   Bluetooth-availability condition. It now remains visible and has a separate
   USB/paired refresh action, OTG/PC guidance, and network form validation.
   Bluetooth status updates while the panel is open; an initial list failure
   no longer leaves a permanent loading message.
3. **USB cancellation and permission loops:** closing a pending transport now
   releases its permission wait and prevents a late open from installing a stale
   connection. Permission replies are matched to the device. Denial/timeout
   waits for explicit Reconnect rather than repeatedly prompting. Identical
   VID/PID devices are deduplicated in discovery and ambiguous selection is
   refused instead of sending to an arbitrary printer.
4. **Bluetooth recovery:** a dedicated exported receiver receives privileged
   Bluetooth state broadcasts; the USB receiver remains private. The handler
   reads actual adapter state rather than trusting extras. Foreground resume
   refreshes permissions/status. A cancelled Classic connection is closed even
   if cancellation raced socket creation.
5. **Duplicate slips after failure:** a failed write could resend the entire
   slip, including bytes already printed. Automatic replay now requires the
   native pre-write `NOT_CONNECTED` refusal. BLE disconnection while waiting for
   an accepted chunk is classified as uncertain delivery. Partial write and
   timeout errors tell the operator to check paper before reprinting. Connection
   recovery for later jobs remains available.
6. **Mobile UI:** consistent blue/neutral cards, field label/focus/error states,
   disabled input and synchronous duplicate-submit protection while saving,
   printer connection hints, scrollable error UI, and initial page loading
   feedback with the workspace hostname.
