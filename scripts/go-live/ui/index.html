Hosting · Vercel

Token: client's Vercel → Settings → Tokens. The login below is your own record.

Where do I get the token?
  1. Log in to the Vercel account the project should live in — the client's email, or your own for the demo (new account → free Hobby plan).
  2. Open vercel.com/account/tokens (avatar top-right → Account Settings → Tokens).
  3. Create Token: name pos-go-live · Scope = that account/team · Expiration = No Expiration (otherwise redeploys stop working later).
  4. Copy it right away — Vercel shows it only once — paste it above, Save. This field is your permanent record.

Token invalid or expired → go-live stops at "get user (is the token valid?)": make a new one, paste, Go live again.

After go-live: the 3 WAF rules (manual, once per cafe)

Vercel → the project → Security → WAF → Custom rules: add the 3 rules that block obvious abuse of the public QR-ordering surface, paths /m and /api/public/* (Hobby allows 3 custom rules). Exact rules: docs/GO-LIVE-CHECKLIST.md §1. The console cannot create these — Vercel has no free API for them.

Realtime (Cloudflare)

Realtime nudges make the Kitchen board and the print host react instantly instead of polling. Create the token in the CLIENT's Cloudflare account: My Profile → API Tokens → Create Token → Custom: Workers Scripts: Edit + Account Settings: Read, limited to that one account. The run deploys the Worker pos-realtime-<slug> there and links it; nothing else changes.

Database · Atlas

SRV must end with the database name (…mongodb.net/pos?…). Network Access 0.0.0.0/0.

Where do I get the URI?
  1. cloud.mongodb.com → log in to the client's Atlas account (or yours for the demo) → Create a cluster → M0 Free, region Mumbai (ap-south-1).
  2. Database Access → Add New Database User → password auth, role Read and write to any database. Keep the password.
  3. Network Access → Add IP Address → 0.0.0.0/0 (Vercel has no fixed IPs).
  4. Cluster → Connect → Drivers → copy the mongodb+srv://… string. Put the real password in and make it end with /pos?retryWrites=true&w=majority — the /pos database name is required.

Product images

Where do I get these R2 values?
  1. dash.cloudflare.com → the client's account → R2 Object Storage. On the R2 overview copy the Account ID (it is also the id in the page URL dash.cloudflare.com/<account-id>/r2). Cloudflare may ask for a card to activate R2 even on the free tier.
  2. Create bucket → name it e.g. pos-<slug> → that name goes into Bucket.
  3. Bucket → Settings → Public Development URL → Enable (type allow). The URL it shows, https://pub-….r2.dev, goes into Public base URL.
  4. R2 overview → Account Details → Manage next to API Tokens → Create Account API token → permission Object Read & Write → scope it to this bucket → Create. Copy Access Key ID and Secret Access Key right away — the secret is shown only once.
  5. After the cafe is live: bucket → Settings → CORS policy → Add, with the cafe's live URL: 
    [{ "AllowedOrigins": ["https://<live URL>"],
   "AllowedMethods": ["PUT"], "AllowedHeaders": ["content-type"] }]

Filled or changed the store on an already-live cafe? Press Go live (not Redeploy): it saves the new env vars on Vercel and redeploys. The seed step is a no-op on a cafe that already has data — settings, admin, tables and menu stay exactly as they are.

Where do I get these Cloudinary values?
  1. cloudinary.com → log in to the client's account → Dashboard: Cloud name is shown under Product Environment.
  2. Settings → API Keys: copy the API key and reveal the API secret (it may ask for your password; unlike R2 it can be viewed again later).

Filled or changed the store on an already-live cafe? Press Go live (not Redeploy) to save the env vars and redeploy; the cafe's data is not touched.

Platform — apex domain

The ONE domain every cafe's web address is a subdomain of, e.g. lucifer.sandbee.in. DNS (the nameservers) stays with your registrar — nothing here changes that.

Hobby plan: 50 domains per project, 200 projects per account, free SSL certificates.

Let's Encrypt: at most ~40 new cafes per week on one apex domain.

Wildcard domains need Vercel's own nameservers — not used here; every cafe's DNS record is added one at a time.
