# P2 Smooth + fast navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every nav tap answers in the same frame, a new screen's frame comes from the CDN with no function and no cold start, deploys land in Mumbai and reach open apps at a quiet moment, and no single failed navigation puts an error page in place of the POS — with no more server load than today.

**Architecture:** four parts, each its own session and merge (owner D8): **A** N0 region guard (deploy script + health + docs); **B** N2 static page frames + N3 warm-from-start / touch prefetch; **C** N1 the navigation-in-progress store, `AppLink` / `navigateTo`, the tap's skeleton, "Still opening", the offline guard; **D** N4 deploy updates at a quiet moment, then the full before/after verification. Pure rules live in `lib/*.ts` with node:test unit tests; wiring is pinned by source tests (`lib/source-pin-utils.ts`'s `stripComments`), as everywhere in this repo.

**Tech Stack:** Next.js 15.5.19 (App Router, webpack), React 19.1, NextAuth v5 (`next-auth/react`), TanStack Query 5, node:test via `tsx`, Vercel Hobby (CLI deploys from the repo root).

**Spec:** `docs/superpowers/specs/2026-11-06-perf-nav-design.md` (approved 2026-11-06). Measurements: `docs/perf/2026-11-06-p2-measurements.md`. Tools: `D:\kd\pos-dev-keep\perf\p2\` (`edge-sim.mjs`, `tap-probe.mjs`, `event-probe.mjs`, `rsc-timeline.mjs`, `cold-rsc.mjs`, `run-taps.sh`, `run-events.sh`, `tab-taps.py`), P1's in `D:\kd\pos-dev-keep\perf\`.

## Global Constraints

- Local only: never deploy, push or send anything; `next build` with `NEXT_TELEMETRY_DISABLED=1`; no connectors; Playwright / `a11y-check.mjs` for browser checks (never chrome-devtools-mcp).
- Only this project's processes and ports (never :3110 / :3130 / :3140); only `pos_scratch_perf_*` databases you create, dropped at the end of the session.
- No new recurring request; no change to printing, the paper (S1 pin, `print-budget.test.ts`), offline KOTs, the realtime room, the money paths.
- WebView 109-safe CSS: no `:has()`, no new CSS features; motion = transform / opacity only; 44 px touch targets; 16 px inputs below 720 px.
- Files ≤ 300 lines; every new `assert` carries a message; a source pin moves only on purpose, and each new pin is proven to bite (break the source, see it fail, restore).
- New test files are added to `apps/cafe/package.json` `"testChain"` (or the root `"test:go-live"` list for `scripts/go-live`).
- Commands (from `apps/cafe`): one file `node --import tsx --test lib/<name>.test.ts`; all `npm test`; `npx tsc --noEmit`; `npx eslint .`. Root: `npm run test:go-live`.
- Words on screen (exact): "Still opening…", "Try again", "Back", "Offline: {screen} opens once the internet is back", "Connecting to the server…", "Retry", "Update ready · Reload", "Updated".
- Constants (exact): `NAV_STILL_OPENING_MS = 8000`, `QUIET_IDLE_MS = 60_000`, `UPDATED_NOTE_MS = 2000`, `INTENT_HOVER_MS = 120`, session retry backoff `[1000, 2000, 4000, 8000]` ms (then every 8000), region `"bom1"`.

## Review Focus

1. A staff member (not admin) on a slow first session answer: no admin row and no admin page may flash; an admin on `/settings` must never be bounced to `/` by a failed session fetch — Task B2's `classifySessionAnswer` tests and the AdminGuard wait.
2. Offline + a tap on a screen the device holds vs one it does not: the held one opens, the other shows the toast and keeps the POS — Task C3's `navDecision` tests.
3. A deploy while a payment dialog is open, a field is focused, the cart has items, an order waits in the outbox, or a print job is leased: never a reload — Task D2's `quietVerdict` table test (each condition alone blocks).
4. A browser device with alerts on after a deploy: never a silent self-reload; the chip shows — Task D2's `quietVerdict` "chip" case.
5. A navigation superseded by another tap, or a tap on the row already open: the second wins / nothing happens, no stuck skeleton — Task C1's `navProgress` tests ("start while pending replaces", "start same href is a no-op", "settle on pathname").
